Compliance & Privacy

Consent & Cookie Modal Reference

Expected consent banner behavior per region across all Fortis games — OneTrust categories, IAB TCF, region flow classification, and per-SDK gating.

ℹ️
How region classification works: During bootflow, the Platform SDK queries the Terra API (compliance/v1/bootflow?gameId=X&countryCode=Y). The response determines whether the player's region requires Explicit, Implicit, or USA consent handling. A fallback to the local ComplianceSequenceDescriptorScriptableMap.asset is used if the API call fails.
How the flow is selected

Explicit Express Consent

EU / UK / GDPR-covered regions
  • OneTrust banner is shown (opt-in required)
  • Consent must be actively given before targeting SDKs activate
  • Full IAB TCF vendor list available in preferences
  • IABTCF TC String generated and stored
  • Accept All / Reject All / Manage Preferences buttons
  • Tailored offers default: opt-out
Legal basis returned by Terra API: expressConsent

Implicit Implied Consent

Canada / Australia / New Zealand / others
  • OneTrust banner is shown (to record consent)
  • Consent is recorded as given by default (opt-out model)
  • Targeting SDKs activate unless player opts out
  • Preference center accessible for changes
  • No full IAB TCF vendor list required
  • Tailored offers default: varies by region config
Legal basis returned by Terra API: impliedConsent

USA US Consent

United States (all states)
  • OneTrust banner may appear for CPRA/CCPA compliance
  • Do Not Sell / Share My Personal Info (DNSM) option
  • California (CPRA): full opt-out rights
  • Targeting SDKs active by default unless opted out
  • Atlas: No age gate slider (NoAgeGate rule)
  • Tailored offers default: opt-in
Legal basis returned by Terra API: impliedUs. API fallback hardcodes USA flow for US.

Default Rest of World

All other regions
  • Banner typically not shown (showBanner = false)
  • ToS + Privacy accepted silently during Age Gate
  • Targeting SDKs treated as enabled (no consent barrier)
  • Consent state: Not Collected (SDKs enabled by default)
Determined by local ComplianceSequenceDescriptorScriptableMap when Terra API unavailable.
Consent architecture
⚙️
OneTrust → IComplianceManagedSdk: After the player interacts with the banner, ControlComplianceManagedSdks() is called. It reads the consent status for each OneTrust category and SDK, then calls Enable() or Disable() on each registered IComplianceManagedSdk. All current implementations gate on the TARGETING category (C0004) and also check the trackers age gate permission — if the player is flagged as underage, targeting SDKs stay disabled even if OneTrust consent is given.
What ShouldShowBanner means
ShouldShowBanner = true
Banner is explicitly required for this player's region. OneTrust's server-side config determined the player needs to consent. The DataConsentStep shows the OneTrust UI.
ShouldShowBanner = false
OneTrust has determined no banner is needed (Rest of World / player already consented). DataConsentStep is skipped. SDK consent state may still be read from cached data.
bannerReason / bannerReasonCode
Diagnostic fields in the OneTrust response indicating WHY the banner is shown (e.g., GDPR, CCPA). Useful for QA to confirm the correct reason code per region.
IABTCF_TCString
Present in EU/UK responses. The IAB TCF Transparency & Consent Framework string. Stored in OT_ConsentString cache and passed on subsequent OneTrust API calls.
🌍
Region classification is server-driven. The Terra API response for each countryCode + stateCode combination returns the correct legal basis. QA can override the detected region using Spire's DebugGeoOverride feature (Spire only) or a VPN. The list below reflects the platform-level classification — individual games may override specific behaviors.
Explicit Consent regions (GDPR)
What happens
Age Gate → ToS/Privacy → OneTrust Banner (opt-in) → ATT (iOS, if trackers permitted) → Attribution init
EU member states United Kingdom Norway Iceland Liechtenstein Switzerland
OneTrust shows the full banner with Accept All / Reject All / Manage Preferences. For UK and EU, the Preference Center includes the IAB TCF vendor list (ad network partners, analytics vendors). An IABTCF_TCString is generated, cached, and passed to the OneTrust SDK on subsequent sessions.
Implicit Consent regions
What happens
Age Gate → ToS/Privacy → OneTrust Banner (shown for recording, consent assumed) → ATT (iOS) → Attribution
Canada Australia New Zealand Brazil South Africa + other implied consent jurisdictions
Banner appears but consent is recorded as given by default. Player may open the Preference Center to change individual category settings. No full IAB TCF vendor list. Direct marketing default varies: Brazil typically defaults to opt-out, Canada to opt-in (server-configured).
USA flow
What happens
Age Gate (Demeter/Spire) or No Age Gate (Atlas) → ToS/Privacy → OneTrust Banner (CCPA/CPRA) → ATT (iOS)
United States (all states)
California (CPRA) players see a "Do Not Sell or Share My Personal Information" link. Other US states may see a simplified banner or no banner based on OneTrust's server config. Targeting SDKs are active by default; player must opt out. Tailored offers preference defaults to opt-in. Atlas skips the age gate entirely for all US players (AgeGateRule = NoAgeGate).
Default (Rest of World)
What happens
Age Gate → ToS/Privacy → No consent banner → Attribution (SDKs enabled by default)
Philippines South Korea Japan Most of Asia-Pacific Most of Latin America + all other regions
ShouldShowBanner = false. No OneTrust consent interaction. All targeting SDKs enabled immediately after Age Gate / ToS, subject to age gate trackers permission.
Direct Marketing & Tailored Offers defaults per region
The Terra API response includes directMarketing and tailoredOffers actions in addition to the tracking flow. These set the initial default state for marketing preferences — IComplianceInitialConsentProvider stores these values and TailoredOffersConsentResolver (Spire) applies them on first login if the player hasn't explicitly set a preference yet.

EU/UK: tailoredOffers defaults to opt-out (legalBasis = expressConsent is absent → opt-out)
US: tailoredOffers defaults to opt-in (set explicitly in USA fallback)
Other: determined by Terra API per-region configuration
📋
OneTrust category IDs are configured in the OneTrust dashboard per game (domain ID). The C-codes below are standard OneTrust defaults. Category consent status is stored in OT_GroupConsents with values: 0 = Not Given, 1 = Given, 2 = Always Active. The ControlComplianceManagedSdks() method reads these values after each consent interaction to enable or disable registered SDKs.
Standard OneTrust categories
Category ID Name Default State What it gates in Fortis games
C0001 Strictly Necessary Always Active Core SDK functions, authentication, save/load, economy. Cannot be disabled. No registered IComplianceManagedSdk uses this category.
C0002 Performance / Analytics Given by default (Implicit/USA) or Opt-in (Explicit) Game performance analytics. Not currently used as a gate by any registered compliance manager — analytics SDKs instead use the TARGETING category for tracking consent.
C0003 Functional Given by default (Implicit/USA) or Opt-in (Explicit) Functional features (e.g. social login, cross-device sync). Not currently used as a primary gate in identified compliance managers.
C0004 Targeting / Advertising Opt-in (Explicit) / Given by default (Implicit/USA) All tracking SDKs are gated here.
• Firebase Analytics (Spire: FIREBASE_ANALYTICS + FIREBASE_ANALYTICS_IMPLEMENTATION)
• Singular attribution (ANALYTICSFG)
• CleverTap engagement (CLEVERTAP)
If C0004 = Not Given → all these SDKs call Disable(). A secondary check on the age gate trackers permission also applies.
IAB TCF integration
🔐
IAB TCF is active for EU/UK (Explicit Consent) regions. The OneTrust API response includes an IABTCF_TCString stored in StorageKeys. The Preference Center exposes the full IAB TCF vendor list (iab2V2Vendors) including ad network partners, analytics vendors, and their declared purposes. The TC String is passed back to the OneTrust API on subsequent banner requests via OneTrustConfig.iabTcfTcString.

Spire uses the native OneTrust mobile SDK (UseNativeOneTrustBanner: 1), which renders the IAB TCF vendor list natively rather than via a custom Unity WebView.
Consent status values
OTConsentStatus Integer value Meaning SDK behavior
AlwaysActive 2 Strictly necessary — always on, user cannot disable SDK Enable() called
Given 1 Player explicitly or implicitly gave consent SDK Enable() called
NotGiven 0 Player explicitly rejected this category SDK Disable() called
NotCollected — No consent interaction yet (e.g., Rest of World / banner not shown) SDK state unchanged — not called by ControlComplianceManagedSdks

proj-spire · PerBlue
OneTrust banner type
Native OneTrust SDK (UseNativeOneTrustBanner: 1) — renders natively, not via Unity WebView. The native SDK handles IAB TCF UI including vendor list.
OneTrust Domain IDs
iOS: 019831da-6374-7fcf-884f-c2f9a4d2cbca
Android: 019831d9-e624-757a-9c0b-03639cce53ac
Combined Age Gate
Always enabled (UseCombinedAgeGate: 1). Age slider combined with ToS/Privacy on one screen.
Registered IComplianceManagedSdks
FirebaseAnalyticsComplianceManager FirebaseAnalyticsImpComplianceManager — both gated by TARGETING (C0004) + trackers age gate permission. Calls FirebaseAnalytics.SetAnalyticsCollectionEnabled(). A separate Update() method re-applies consent after Firebase initializes (prevents race condition).
IAB TCF / AdMon banner
For UK and EU players, the native OneTrust SDK shows the full IAB TCF banner including the vendor consent list (Google, AppLovin, analytics partners). The TC String (IABTCF_TCString) is stored and passed back on subsequent OneTrust API calls. This is what the QA team refers to as the "IAB AdMon banner" — it includes ad network vendors (AppLovin MAX) in the vendor list.
AdMon (Rewarded Video)
AppLovin MAX (SpireAdMonFeature) is controlled by a GrowthBook kill switch (IKillSwitch.Feature.adMon), not directly by OneTrust consent category. S2S callbacks go to ExternalPostbacks/api/v1/admon/rewards. Ads are rewarded video only; not shown to opted-out users due to the platform-level kill switch.
Tailored Offers
TailoredOffersConsentResolver sets the initial preference on first login based on Terra API regional config (IComplianceInitialConsentProvider.ShouldEnableTailoredOffers()). EU = opt-out default. US = opt-in default.
QA geo override
DebugGeoOverride in Spire config — allows overriding the detected region in debug/dev builds without a VPN. Set to the desired country code to test region-specific flows.

Mergemon
mergemon · TypeScript / Web SDK
Platform
Web game using @fortis/sdk (TypeScript). Mirrors the Unity Platform SDK bootflow in web form.
Current release regions
US PH (Philippines) EU — not released UK — not released
Controlled by complianceRules.json: defaultRule.released = false. Only US and PH have released: true. All other regions blocked at game level.
Consent flow (active regions)
USA flow + Philippines (Default flow). GDPR/Explicit Consent flow not exercised in production — no EU/UK players reach the game.
Age gate
Web DOM overlay slider (0–65+) via fortisAgeGateDialog in complianceDialogs.ts. Underage result cached in localStorage with a 2-hour TTL — underage players are blocked for 2 hours on return.
DNSM toggle
Pre-OneTrust CCPA stopgap: setNonEssentialTrackingDisabled() stored at localStorage['mergemon_tracking_preference_v1']. "Do Not Sell or Share My Personal Information" toggle in the Settings menu.
Consent preferences
setFortisConsentPreferences() sets dataCollectionAllowed and adsAllowed in the SDK context based on player's consent choices.
IAB TCF
Not active — no EU/UK players reach the game in the current release state. The web SDK supports IAB TCF regions in principle (gdpr/nonGdpr/usa flows defined in SDK), but the complianceRules.json gates them out.
Theme
Custom campfire theme with TosPopupBG.webp background — visually different from Unity game consent UIs.
⚠️
EU/UK QA note: Testing the GDPR/Explicit Consent or IAB TCF flow for Mergemon requires either a release region expansion or a test environment override. The current complianceRules.json blocks all non-US, non-PH players at the release gating level before the SDK consent flow is reached.
